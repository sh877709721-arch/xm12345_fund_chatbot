# GraphRAG 提示词优化文档

## 概述

基于 Assistant.py 中厦门市医保政务服务助手的成功经验，对 GraphRAG 本地搜索提示词进行了全面优化，使其更符合医保政务服务场景的需求。

## 主要改进

### 1. 角色定位优化

**修改前:**
```
您是一位智能助手，负责回答有关所提供表格中数据的问题。
```

**修改后:**
```
你是一名亲切、耐心的厦门市医保政务服务助手，名叫小E，专门基于知识图谱数据回答市民关于医保政策问题。
```

**改进点:**
- 明确身份：厦门市医保政务服务助手
- 增加人格化：名叫小E
- 强调专业性：基于知识图谱数据
- 定位服务对象：市民

### 2. 规则体系完善

**新增的重要规则 (参考 Assistant.py):**
- ✅ 多问题逐一处理
- ✅ 内容质量过滤
- ✅ 禁止编造推测
- ✅ 同义转写能力
- ✅ 关注实体关系
- ✅ 医保待遇严格相关性
- ✅ 信息不全处理
- ✅ 超出范围处理
- ✅ 热线转接规范
- ✅ 字数控制 (200-300字)
- ✅ 基于知识图谱推理

### 3. 知识图谱引用规范

**修改前:**
```
[数据: <数据集名称> (记录 ID); <数据集名称> (记录 ID)]
```

**修改后:**
```
[知识图谱: <数据类型> (记录ID); <数据类型> (记录ID)]
```

**数据类型定义:**
- **实体**: 政策概念、机构、人员等
- **关系**: 实体间的关联和依赖
- **社区**: 相关的政策群体
- **报告**: 详细的政策说明
- **文本单元**: 原始政策文档内容

### 4. 数据质量检查机制

**新增检查项:**
- 📋 知识图谱证据支持验证
- 📋 数据引用准确性检查
- 📋 数据不足时明确说明
- 📋 模糊关系谨慎处理

### 5. 回答结构优化

**标准回答结构:**
```markdown
## 直接回答
针对用户问题的直接解答

## 政策说明
相关政策的详细解释

## 操作步骤
具体的办理流程（如有）

## 注意事项
需要特别关注的条件和要求
```

## 设计原则

### KISS 原则应用
- 简洁明了的规则表述
- 清晰的层次结构
- 易于理解和执行

### SOLID 原则体现
- **单一职责**: 专注于医保政务服务
- **开放封闭**: 易于扩展新的医保政策类型

### DRY 原则实践

- 保持与现有服务的一致性
- 统一的政务服务质量标准

## 使用场景示例

### 查询示例
**用户问题:** "怎么交医保？"

**优化后的回答:**
> 您好！我是厦门市医保政务服务助手小E。关于医保缴费，我为您整理了以下信息：
>
> **医保缴费方式 [知识图谱: 实体 (15, 16), 关系 (23); 文本单元 (5, 7)]**
>
> ## 缴费渠道
> 1. 线上缴费：通过厦门医保APP或微信公众号
> 2. 线下缴费：到就近的医保经办机构或合作银行网点
>
> ## 注意事项
> - 确保在每月25日前完成缴费 [知识图谱: 社区报告 (1)]
> - 缴费金额根据缴费基数和比例计算 [知识图谱: 实体 (34, 46, 64, +more)]
>
> 如有特殊情况，建议拨打12345热线咨询。
